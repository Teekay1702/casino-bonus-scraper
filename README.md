# Casino Bonus Tracker

Scrapes bonus text for three casinos from one public source, uses an OpenAI model to turn the free text into structured fields, and shows the result on a static comparison page.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate          # Git Bash on Windows: source .venv/Scripts/activate
                                   # Windows PowerShell:  .venv\Scripts\Activate.ps1
pip install -r scraper/requirements.txt
cp .env.example .env               # Windows cmd: copy .env.example .env
```

Edit `.env` and set:

```
OPENAI_API_KEY=your-key-here
OPENAI_MODEL=your-model-name
```

- Get a key from the OpenAI platform and make sure the account has API billing or credits. A ChatGPT subscription does not include API credits.
- `.env` is git-ignored. The key is only read by the Python scraper and is never part of the website.
- The scraper sends `reasoning_effort="none"`, so `OPENAI_MODEL` must be a model that accepts that setting.

## Run the scraper

```bash
python scraper/scraper.py --dry-run   # fetch + parse only: no key, no cost, writes nothing
python scraper/scraper.py             # full run: calls the OpenAI API, writes data/casinos.json
```

The scraper stops with a clear error, and writes nothing, if:
- robots.txt disallows the URL, can't be fetched, or returns 401/403
- the page returns anything other than HTTP 200
- the selectors match nothing, or fewer than three casinos have usable terms
- `OPENAI_API_KEY` is missing, or the API returns an error (the message includes a hint for auth and billing problems)
- fewer than three records end up with a casino name and bonus offer

## Check the output

Open `data/casinos.json` and confirm:
- there are exactly three records
- each value matches the `original_terms` text
- values the terms don't state are `null` (shown as "Not stated" on the page), not guessed

## Source notes

- Source: `https://www.casinomeister.com/casino-bonuses/`. Read the site's terms of use yourself before running the scraper or publishing its content.
- Each casino is an `li.casino-item`. The name and `source_url` come from the casino's review-page link; the offer and terms come from the listing text.
- The "Visit" and "Terms Apply" links are `/goto/` affiliate redirects. The scraper never uses or follows them.
- Most casinos on the page show only generic "Restrictions Apply" text instead of their own terms. The scraper skips those and takes the first three casinos that publish real terms, so records are not built from boilerplate. Some terms don't mention a wagering requirement, which then shows as "Not stated".
- `original_terms` is copied from the source and will be public once the JSON is published. If the site's terms restrict republishing, remove that field from the JSON.
- If the site starts blocking plain HTTP requests, or its HTML changes, the scraper errors out. Do not bypass blocks; choose another source or update the selectors in `SOURCE_CONFIG`.

## How it works

1. `scraper.py` checks robots.txt, fetches the page with `requests`, and parses the casino blocks with BeautifulSoup. No browser automation is used.
2. For each of the three selected casinos, one OpenAI API call (a forced function call with a strict schema) returns `bonus_offer`, `max_bonus` and `wagering_requirement`, or `null` for anything not stated. This is the only LLM step.
3. Validation keeps only string values, and drops any value containing a number that doesn't appear in the original terms, so the model can't invent figures.
4. Results are written to `data/casinos.json`. `web/app.js` fetches that file and renders the table, showing "Not stated" for nulls and a link to the source page for each record.

Data flow: source page, then `requests` and BeautifulSoup, then OpenAI structuring, then validation, then `data/casinos.json`, then the static page.

## Deploy to GitHub Pages

1. Create a GitHub repository and push this project to the `main` branch. Commit `data/casinos.json`. Do not commit `.env`; run `git status` first to confirm it isn't listed.
2. In the repository, go to Settings, then Pages, and set Source to **GitHub Actions**.
3. The workflow in `.github/workflows/pages.yml` publishes `web/` and `data/` together. Open the Actions tab and wait for the run to finish.
4. Open `https://<your-username>.github.io/<repo-name>/` and confirm the table loads. The page uses relative paths, so it works under the repo-name subpath.

## Refresh the data

```bash
python scraper/scraper.py
git add data/casinos.json
git commit -m "Update data"
git push
```

The push triggers the workflow, which redeploys the site. The scraper never runs on GitHub Pages.
